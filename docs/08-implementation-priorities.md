# 移动端实施优先级

更新：2026-09-13。状态：执行排序草案；技术栈与可靠恢复目标已确认，具体视觉方案和上游新增协议仍需评审。

完整功能清单、里程碑 M0–M6、上游契约依赖与近期执行清单见 [总路线图](09-roadmap.md)。

本排序不以“复刻桌面页面数量”为目标，而以尽快证明移动端核心价值为原则：离开时放心，回来时接得上；操作不会重复，多个任务的真实状态看得清。

## 排序原则

1. 先消除会造成重复执行、丢结果、串 Team 或错误状态的风险，再增加页面数量。
2. 每个阶段交付可在 Android 真机验证的纵切，不堆积只有 mock 数据的页面。
3. 服务端权威状态、SQLite 本地副本、Outbox 操作意图、草稿/锚点分别建模。
4. 依赖上游的新协议先以契约测试和脱敏夹具锁定，不在客户端伪造已支持能力。
5. iOS 从架构和配置上保持可编译路径，但当前开发与验收以 Android 为先。

## Now：P0 工程基线与风险验证

目标：从静态目录骨架变成可安装、可调试、可测量的 Expo development build。

| 顺序 | 工作项 | 完成标准 |
| --- | --- | --- |
| 0.1 | Expo SDK、Expo Router、TypeScript strict、development client | 依赖兼容检查、类型检查和 JS bundle 通过；Android development build 可安装 |
| 0.2 | Android 真机开发链路 | USB 调试可连接，手机锁定竖屏；系统返回、安全区、中文输入法和键盘遮挡完成冒烟验证 |
| 0.3 | SQLite / SecureStore / 生命周期最小探针 | 进程被终止后测试记录仍在，凭据不进入普通数据库或日志 |
| 0.4 | 长文本与流式渲染基准 | 固定夹具测出 100 增量/秒、长消息、历史前插和锚点恢复的基线；据此选择列表与 Markdown 实现 |
| 0.5 | 上游移动契约对齐 | 明确 discovery、历史/live 边界、invocation 结果查询、幂等首次建会话和设备登录；建立脱敏 fixtures |

0.1 已完成。0.2 的 Android SDK、原生构建、实体机安装、Metro LAN、竖屏、安全区、返回键和键盘避让均已验证；真实中文 IME 候选词组合测试因当前设备只安装了英文 AOSP 键盘而保留为人工复核项，不阻塞后续风险验证。0.3 已在实体 Android 设备完成：探针经历后台、强制终止、冷启动和覆盖安装后仍可恢复，SecureStore 记录与 SQLite 公共记录匹配，秘密标记未进入 SQLite 或测试输出。

P0.3 之后的执行顺序是先做 0.5 上游移动契约对齐，再做 0.4 长文本与流式渲染基准；协议边界先确定，可避免性能夹具建立在错误的历史/live 或 invocation 语义上。

## Next：P1 可靠聊天纵切（最高业务优先级）

目标：完成一次真实任务，并证明 App 离线、后台或被杀后仍能恢复，且服务端只准入一次。

建议严格按以下依赖顺序实现：

1. **连接与身份**：部署资料、登录、能力发现；本地隔离键固定为 deployment + account + team。
2. **本地持久层**：SQLite migration、会话/turn/run 副本、草稿、阅读锚点和 checkpoint。
3. **会话读取**：Bot 与会话列表、历史分页、当前 Session 恢复；先做只读真数据。
4. **持久发送 Outbox**：发送前落盘不可变 payload 与 invocation ID；ACK 丢失后查询或同 ID 重试。
5. **实时运行投影**：runtime snapshot/delta 的 epoch/seq reducer、缺口重订阅、历史 committed-through 交接。
6. **聊天 UI**：原生文本输入、合批流式块、工具摘要折叠、明确的连接/同步/操作/Run 四类状态。
7. **控制闭环**：停止、审批、回答和 follow-up/steer 按能力显示；control ID 持久化并核对最终结果。
8. **恢复验收**：发送 → 后台 → 杀进程 → 服务端完成 → 冷启动回原位置，结果完整且无重复 run/turn。

P1 不包含漂亮首页、全套 Bot 设置、推送、远程桌面或完整文件编辑器。若关键 P0 协议尚未落地，可先完成当前服务器的明确降级模式，但不得声称满足完整长离线保证。

## Then：P2 并行任务与移动首页

目标：让用户在约 20 个并行会话中快速找到真正需要处理的事项，再回到原聊天位置。

1. 当前 Team 内跨 Bot 的运行摘要、待审批/待回答、异常和新结果。
2. 首页“继续上次会话 → 等你处理 → 正在运行 → 新结果/最近会话”。
3. 会话搜索、Bot 筛选、稳定排序与“有新活动”提示。
4. 待处理事项进入上下文、处理竞争结果、返回原锚点。
5. 会话切换时独立恢复草稿、附件引用、展开状态和阅读锚点。

进入 P2 前需要定稿首页低保真方案，并确认上游聚合 feed 或可接受的过渡连接策略。

## Later：P3 日常资源能力

按“查看结果”优先于“手机上做完整开发”排序：

1. 聊天附件和文件产物：Markdown/文本、代码、图片、下载与系统分享。
2. 资源页文件浏览、小文件上传；明确 location/path/revision 和工作文件/产物/本地副本差异。
3. 执行环境只读详情：类型、在线状态、新鲜度、逐项 capabilities、当前任务来源。
4. 模型、Agent 和执行位置选择；发送意图绑定创建时的选择。
5. 定时任务列表、常用频率创建和执行记录。
6. Bot Memory 条目列表、搜索与详情。

通知可在真实内测证明“必须后台获知结果”时前移，但不能替代前台完整同步。

## After：P4 管理与扩展

- Bot 常用设置、工具审批策略、连接服务和能力目录。
- Team 成员与权限、用量/订阅只读概览、账号与设备会话管理。
- 文件编辑与冲突处理、Memory 内容管理、环境级幂等操作。
- iOS 最小编译、设备行为验证与发布准备。

## 明确后置

以下功能价值存在，但移动交互、权限和恢复成本高，不应阻塞可靠聊天：

- Terminal、Browser、Desktop 深度远程交互与手机分屏。
- Workspace 快照恢复、停止/删除环境、资源限制修改。
- Hooks 编辑与运行测试、复杂 MCP/Provider 配置、完整 Bot 备份恢复。
- 关系图首屏、批量文件管理、文件夹上传、完整代码编辑器。

## 每阶段共同门槛

- 类型检查、依赖兼容检查、受影响测试和 Android 真机冒烟通过。
- 不用生产账号数据做故障注入；使用独立测试部署和脱敏夹具。
- 新增协议有 capability/version、未知语义处理和契约测试。
- 连接、同步、操作、Run 状态不混为一个“在线/运行中”标签。
- scope 切换后，旧响应和旧 Outbox 绝不写入或投递到新 Team。
- 新视觉页面先完成低保真方案选择，再进入实现。

## 当前最近的三个里程碑

1. **M0：可安装骨架**——本机配置与 bundle 通过，实体 Android 设备可打开四区占位页。
2. **M1：恢复风险样例**——SQLite、SecureStore、生命周期和英文键盘避让已有实机记录；仍需完成长文本/锚点基准、真实中文 IME 复核，并为协议差距确定 owner。
3. **M2：可靠聊天 Alpha**——连接真实测试部署并通过 ACK 丢失、断网、杀进程、历史/live 竞态和跨 Team 隔离验收。
