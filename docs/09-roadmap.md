## 1. 北极星与取舍规则

**离开时放心，回来时接得上。** 内容完整、状态正确、操作不重复、阅读位置保留。

取舍时按顺序问：

1. 会不会造成重复执行、丢结果、串 Team、错误状态？——先做防护。
2. 能不能在 Android 设备上端到端验证？——不能验证的不算完成。
3. 是否依赖尚未存在的上游协议？——先锁契约，或定义明确的降级模式。
4. 是“查看/控制”还是“在手机上做完整开发”？——前者优先。

## 4. 功能优先级清单

优先级定义（与阶段无关，只表示对产品价值的重要度）：

- **必须**：缺了该里程碑不成立。
- **应该**：该里程碑内应交付，可在压力下延后一个里程碑。
- **可以**：有余量再做。
- **暂不**：明确后置，见第 6 节。

## 5. 上游契约依赖（P0.5 的范围）

这些是客户端里程碑的**阻塞项**。P0.5 为每项产出：现状证据、差距、owner、脱敏 fixture、以及上游未落地时的客户端降级模式。

| ID | 契约 | 阻塞 | 现状（来自 `02`） | 未落地时的降级 |
| --- | --- | --- | --- | --- |
| U1 | 能力发现 / 版本协商 | M2 | 未见统一 discovery | 最低支持 v0.17.0（可能上调，见 `contracts/README.md`）；能力按证据逐项探测，未知能力隐藏 |
| U2 | 移动设备登录与续期 | M2 | `/auth/login`、`/auth/refresh`，无独立 refresh token | 过期后要求重新登录；不在 URL 中放 token |
| U3 | 历史 / live 边界（committed-through） | M2 | 两条读路径，无显式交接点 | 订阅快照后重拉最近一页历史并按 turn ID 去重 |
| U4 | 按 invocation 查询准入结果 | M2 | ledger 有 `GetByInvocation`，未暴露 | 同 invocation ID 重发，依赖服务端 fingerprint 幂等 |
| U5 | 首次建会话的幂等 | M2 | 需确认 | 客户端先建会话并持久化 session ID，再发送 |
| U6 | Team 内跨 Bot 运行摘要 / 待处理聚合 | M3 | 仅每 Bot 的 WS 与 SSE | 对前 N 个活跃 Bot 分别订阅（有上限）；见 [contracts/u6-run-summary.md](../contracts/u6-run-summary.md) |
| U7 | 文件 location / path / revision / asset 身份 | M4 | Bot 文件树 | 只读、无版本保证，标注缓存时间 |
| U8 | 环境状态新鲜度与逐项 capabilities | M4 | 部分状态可见 | 只展示在线/离线，隐藏细项 |
| U9 | 环境级操作身份、幂等与影响范围 | 暂不 | 未确认 | 不提供操作 |
| U10 | 推送通道（FCM / 无 GMS 替代） | M4 | 未确认 | 仅前台同步与应用内提醒 |

**M2 的硬门槛：** U1–U5 要么上游已落地，要么降级模式已实现并在 UI 中如实表达（不宣称满足完整长离线保证）。

## 6. 明确后置（暂不）

价值存在，但移动交互、权限或恢复成本过高，不阻塞 M2–M4：

## 7. 并行工作流

M2 是 XL 规模，可以拆成互不重叠的轨道，减少串行等待：

| 轨道 | 内容 | 可并行的前提 |
| --- | --- | --- |
| A 领域核心 | reducer、Outbox 状态机、隔离键、同步检查点（纯 TS + 单元测试） | 仅需 U3/U4 的 fixture |
| B 数据层 | SQLite migration、仓储接口、事务边界 | A 的实体定义 |
| C 传输层 | REST 客户端、WS 连接管理、重连与鉴权 | U1/U2 契约 |
| D UI | 聊天列表、Markdown 块渲染、输入区、状态条 | P0.4 结论 + 低保真评审 |
| E 验收 | 故障注入脚本（断网、杀进程、ACK 丢失）、测试部署 | 独立测试部署可用 |

依赖顺序不变：A → B，C 独立，D 依赖 P0.4，E 贯穿全程。

## 10. 风险登记

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| U3/U4 上游长期不落地 | M2 只能交付降级模式 | P0.5 尽早给 maintainer 差距表；降级模式在 UI 如实标注 |

| RN 长文本性能不达预算 | 聊天体验差 | P0.4 先定位瓶颈层级，再换库或下沉原生；不重开框架选型 |
| MIUI 等厂商后台限制 | 通知与后台同步不可靠 | 以前台完整同步为正确性基础，通知只做提醒 |
| 无 GMS 设备 | FCM 不可用 | U10 需确认目标设备；准备长连接或厂商通道备选 |
| 原生目录与 `app.json` 混合配置 | 配置不同步导致 APK 与预期不符 | 改原生配置时明确选择 Prebuild 或手工同步，并在 release 构建验证 |
| 无版本控制 | 无法回滚、无法协作 | PF-01 作为当前冲刺第一项 |
